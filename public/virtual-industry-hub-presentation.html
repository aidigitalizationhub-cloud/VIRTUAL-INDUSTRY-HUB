02 | One platform, five perspectives

Every role gets a focused path into the innovation ecosystem.

Researchers

Disclose work, track TRL stages, manage documents and respond to partners.

Students

Find labs, projects, mentorship and opportunities to contribute.

Industry partners

Publish challenges, find expertise and submit targeted interests.

Investors

Explore promising pipelines and initiate structured conversations.

Administrators

Review disclosures, govern publication and audit AI-assisted decisions.

03 | The core workflow

From disclosure to partnership, with governance at every step.

Researcher

Creates a disclosure and uploads evidence.

→

AI screening

Structures information and identifies signals.

→

TTO / IP review

Specialists assess evidence and findings.

→

Publication

Super Admin decides what becomes visible.

→

EOI / match

Partners and investors start a project-linked conversation.

Key idea: AI accelerates review; accountable people remain responsible for decisions.

04 | AI-assisted intelligence

Useful AI, without making the system a black box.

Hybrid matching

Embeddings and vector search find candidates. Deterministic scoring keeps the ranking explainable. An AI model adds qualitative reasoning.

News intelligence

Vetted biomedical sources are synchronized into a searchable feed with summaries and source context.

Structured extraction

Uploaded documents can be transformed into validated project and profile information.

Decision provenance

Provider, model, prompt version, timestamp and result summary are recorded for auditability.

05 | TTO / IP governance

Evidence is reviewed before it becomes a public claim.

The platform separates researcher submissions, AI advisory findings, specialist review and final publication decisions.

Evidence queue

Files begin as pending and are visible only to authorized reviewers.

Specialist findings

TTO/IP reviewers record findings, links and recommendations with an audit trail.

Final decision

Super Admin can publish, restrict, hold confidential, request information or reject.

“The platform makes the path from evidence to opportunity visible, reviewable and accountable.”

06 | Technical architecture

A practical full-stack foundation for a governed marketplace.

React 19 SPA

Role-based dashboards, project discovery, inbox, localization and theme support.

→

Express API

Better Auth sessions, validation, authorization, rate limits and domain routes.

→

Supabase platform

PostgreSQL, pgvector, RLS, private storage and controlled database functions.

Architecture principle: the browser requests capabilities; the server decides identity, ownership and access.

07 | Security by design

Private research deserves more than a hidden button.

01
Identity

Better Auth provides the application session. The canonical user ID links profiles and ownership.

02
Authorization

Server routes enforce role, owner, participant and reveal-approval checks.

03
Data layer

RLS, foreign keys, constrained workflows and restricted RPC privileges protect the database.

04
Storage

The project bucket remains private. Authorized APIs return short-lived signed URLs.

05
Quality gates

Type-checking, automated tests and production builds run before changes are shipped.

08 | What has been delivered

A working platform with a hardening path.

Delivered

Role-based portals, project workflows, EOIs, conversations, bookmarks, challenges, matching, AI provenance and private storage routes.

Verified

35 automated tests passing across upload validation, scoring, AI schemas, RLS invariants and authorization boundaries.

Operational lesson

Production deployment must package the bundled Express server as a Vercel function, not import an unbundled TypeScript file.

Next horizon

Durable AI jobs, dashboard bootstrap APIs, deeper integration tests, metrics, tracing and constraint validation.
